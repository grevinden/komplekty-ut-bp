## Задача: набор УТ → комплект в БП (постановка 03.11.2026)

**Статус: исследование и фиксация на сайте закрыты 03.11.2026, модель
пересмотрена вечером 03.11.2026.** Решение — схема E «набор разворачивается в
УТ, товарные строки в БП заменяются строкой комплекта постобработкой, услуги
идут штатно» (§5.13, §7.8, ТК-12). Одна карточка комплекта на набор; на каждую
продажу — своя спецификация и своя сборка (ТК-14). Ответы оператора — раздел 5,
открытые вопросы — раздел 7. Дальше — внедрение на боевой паре.

### Постановка (дословно по смыслу)

- В УТ менеджеры при формировании заказа формируют **набор**, проводят его через
  сделку и продают **набором**.
- При экспорте в БП товары из набора должны **объединиться в комплект**, который
  соответствует идентификации исходного набора. Возможно, для каждой версии
  набора нужен новый комплект.
- Если набор содержит **услуги**, они должны попадать в БП штатным обменом.
- **Только товары** должны превращаться в комплект в БП.
- Главный вопрос: расширять схему обмена или делать иначе? — **Ответ: не
  расширять.** Все добавления живут в БП и запускаются после загрузки.

### Рабочая гипотеза (проверена)

Гипотеза «контур из двух частей» подтвердилась: правила обмена переносят
реализацию и строки, комплект в БП собирается отдельным шагом после загрузки.
Идентификатор набора в сообщение не приходит, поэтому связь «продажа →
комплект» либо указывает оператор, либо набор помечается в самом обмене.

### 5. Ответы оператора (получены 03.11.2026)

- [x] **Набор** — элемент справочника номенклатуры с составом; при изменении
      состава меняется версия.
- [x] **Версия** — «та самая версия, которая есть у каждой ссылки у каждого
      объекта в 1С».
- [x] **Уточнение 03.11.2026 (вечер):** отдельный комплект на каждую версию не
      нужен. Карточка комплекта одна, а состав каждой продажи живёт в её
      спецификации и сборке; в наименовании — только название набора. Пример
      владельца: компьютер за 1 000 и компьютер за 300 — одна строка «компьютер»
      и цена, но разные спецификации сборки. Модель заменяет прежнее «на каждую
      версию — новый комплект» (`cfg/EVIDENCE-2026-11-03-spec-na-prodazhu.md`).
- [x] **Хотим обойтись расширением только в БП**, без правки схемы обмена.
- [x] **Отдельный документ сборки в БП нужен** — сейчас бухгалтер создаёт
      комплект вручную после звонка менеджера.
- [x] **В БП есть приход комплектующих**; продажа должна пройти одной строкой,
      как в УТ.
- [x] **Выручку не делят**: стоимость товаров складывается, доли комплекта — из
      веса в общей стоимости; услуги остаются отдельными строками.
