# Прогон 06.11.2026: пометка набора в сообщении — рабочие имена и количество

**Базы:** УТ — УправлениеТорговлей 11.5.22.186, каталог `/tmp/opencode/exch/ut`,
пользователь `Администратор`. БП — БухгалтерияПредприятия 3.0.208.14, каталог
`/tmp/opencode/exch/bp`, без пользователя. Платформа 8.3.27.2342, файловые
копии демо-баз. Прогон — 06.11.2026, 06:58–07:40 MSK.

**Постановка:** закрыть D2 (пометка набора не попадает в исходящее сообщение),
D7 (асимметрия wire-имён `КомплектыОбмен_*` в УТ и `КомплектыБП_*` в БП) и D8
(количество наборов жёстко равно 1) — см.
[`PLAN-2026-11-05-dorabotka.md`](PLAN-2026-11-05-dorabotka.md), §3, §6.

**Связанные протоколы:**
[`EVIDENCE-2026-11-05-cross-ut-bp.md`](EVIDENCE-2026-11-05-cross-ut-bp.md) —
сквозной обмен до правок;
[`EVIDENCE-2026-11-06-dorabotka.md`](EVIDENCE-2026-11-06-dorabotka.md) — журнал

## 1. Что было не так в коде

Модуль `КомплектыУТ/МенеджерОбменаЧерезУниверсальныйФормат` до правки:

1. `ИнициализироватьРасширениеПравилаКонвертацииОбъекта` вызывался на **таблице**
   правил конвертации (`ПравилаКонвертации`), а штатный API принимает **строку**
   ПКО: у таблицы нет поля `Расширения`. Вызов падал, `Попытка` его глушила.
2. Свойства табличной части искались в `ПравилаКонвертации.Свойства` — это
   таблица свойств **самого объекта**; свойства ТЧ лежат в
   `СвойстваТабличныхЧастей` соответствующей строки ПКО.
3. Заполнение пометки шло через `КомпонентыОбмена.ФабрикаXDTO` и несуществующую
   процедуру `УстановитьРасширенноеСвойствоXDTO` — падало на неопределённой
   `ФабрикаXDTO` (D9), обе `Попытка` глушили ошибку.
4. Количество наборов было литералом `1` (D8).

В БП метаданные документа объявляли реквизиты `КомплектыБП_*`, а УТ писала
`КомплектыОбмен_*` (D7), то есть даже при заполненной пометке приёмник искал
другие имена.

## 2. Что сделано

`КомплектыУТ/МенеджерОбменаЧерезУниверсальныйФормат`:

- `КомплектыУТ_ДополнитьПКООтправка` находит строку ПКО
  `Документ_РеализацияТоваровУслуг_Отправка`, инициализирует расширение на
  **строке**, ищет свойства ТЧ по `ТЧФормата = "Товары"` и добавляет три ПКС;
- `КомплектыУТ_ЗаполнитьПометкуОтправка` пишет пометку не в XDTO, а в **таблицу
  значений `Товары`** (`ДанныеXDTO.Товары`), которую движок сам превращает в
  XDTO: `НомерСтрокиДокумента` → три колонки `КомплектыОбмен_*`;
- количество наборов считает `ОпределитьКоличествоНаборов`: `Количество` строки
  делится на количество этой комплектующей в одном наборе
  (`НаборыВызовСервера.ВариантКомплектацииНоменклатурыПоУмолчанию` +
  `Справочники.ВариантыКомплектацииНоменклатуры.ПолучитьКомплектующиеНоменклатуры`),
  округление до целого, минимум 1; при любой ошибке — 1 и запись в журнал
  регистрации.

`КомплектыБП/Documents/РеализацияТоваровУслуг.xml`: реквизиты ТЧ «Товары»
переименованы `КомплектыБП_*` → `КомплектыОбмен_*` (D7). Имя теперь одно на пару
баз, его же читает ядро `КомплектыОбмен_Пометка` (D10).

`КомплектыБП/МенеджерОбменаЧерезУниверсальныйФормат13`: в
`ОбработатьПередЗаписью` передаётся `ДанныеИБ`, иначе для найденного документа
пометка искалась в ещё не записанном объекте.

## 3. Прогон

Продажа двух наборов в УТ (задание: `набор = Артон`, `количество = 2`):

```
строка 1: Кровать | набор: Мебельный гарнитур "Артон" | кол-во 2,000 | сумма 9 000,00
строка 2: Туалетный столик | ... | кол-во 2,000 | сумма 3 900,00
строка 3: Тумбочка прикроватная | ... | кол-во 4,000 | сумма 5 760,00
строка 4: Шкаф 3-дверный | ... | кол-во 2,000 | сумма 9 600,00
итог по строкам: 28 260,00
записан: Реализация товаров и услуг ТД00-000005 dated 06.11.2026 7:15:00
```

Выгрузка: сообщение №11, 180 369 байт
(`d8-02-ut-vygruzka-11.txt`). Проверка файла сообщения:

```
КомплектыОбмен_НаборУИД: 40 вхождений
КомплектыОбмен_Набор: 80
КомплектыОбмен_КоличествоНаборов: 40
КомплектыБП_НаборУИД: 0
```

Значения `КоличествоНаборов` по строкам сообщения:

```
20 строк — пусто (строки объектов без набора)
12 строк — 1
 8 строк — 2
```

Строки с `2` — четыре комплектующие продажи ТД00-000005 (2 набора). УИД набора во
всех заполненных строках один: `b0d58352-3fe9-11e4-ab12-000d884fd00d`.

Загрузка в БП: сообщение №11 принято, отказ — нет (`d8-03-bp-zagruzka-11.txt`).
В БП создан документ `ТД00-000005` со свёрнутой строкой
`Мебельный гарнитур "Артон"`, Кол=2, Цена=16 485, Сумма=32 970
(`d8-05-bp-stroki-dokumentov.txt`), спецификация «Реализация ТД00-000005 от
06.11.2026» с владельцем-карточкой (`d8-06-bp-specifikaciya.txt`) и проведённая
сборка `0000-000045` (`d8-07-bp-sborka.txt`).

## 4. Вывод

- D2 закрыт: пометка доезжает до приёмника и запускает свёртку.
- D7 закрыт: в сообщении только `КомплектыОбмен_*`, метаданные БП объявляют те же
  имена.
- D8 закрыт: для продажи двух наборов приёмник свернул четыре комплектующие в
  одну строку с количеством 2 и суммой 32 970.
- Остаточное ограничение: при неудачном чтении состава варианта комплектации
  количество наборов принимается равным 1 — это осознанный fallback, он пишется
  в журнал регистрации (`КомплектыОбмен.Обмен`, уровень «Информация»).
