## 3. Сигнатура ДобавитьПКС: чем наша пара отличается от статьи 2023 года

В обеих базах сигнатура одинаковая, **шесть** параметров:

```bsl
// trd: МенеджерОбменаЧерезУниверсальныйФормат/Ext/Module.bsl:65097
// buh: МенеджерОбменаЧерезУниверсальныйФормат13/Ext/Module.bsl:17160
Процедура ДобавитьПКС(РодительПКС, СвойствоКонфигурации, СвойствоФормата,
        ИспользуетсяАлгоритмКонвертации = 0,
        ПравилоКонвертацииСвойства = "", ПространствоИмен = "")
```

В статье metod8dev/6013 (формат 1.11, 2023 год) пример вызова передаёт
`ПространствоИмен` **пятым** аргументом:

```bsl
ДобавитьПКС(СвойстваОбъекта.ЭтоКлючевоеПоле, "МойКодКлассификации",
    "МойКодКлассификации", 1, ПространствоИмен);  // по статье
```

В нашей паре пятым встанет `ПравилоКонвертацииСвойства`, поэтому для
расширенного свойства с алгоритом выборки надо писать
`…, 1, "", ПространствоИмен`, а со вложенным правилом —
`…, , "Справочник_ЕдиницыИзмерения", ПространствоИмен`. Типовой пример
строки со вложенным правилом в дампе УТ:
`МенеджерОбменаЧерезУниверсальныйФормат/Ext/Module.bsl:45217`
(`ДобавитьПКС(СвойстваШапки, "ВидНоменклатуры", "ВидНоменклатуры", , "Справочник_ВидыНоменклатуры")`).

Шаблон из статьи механически переносится, но номера позиций аргументов —
**не** переносятся: это отдельная грабля при переносе рецепта 2023 года на
1.20 [ВЫВОД по дампу].

## 4. Как механизм устроен в коде БСП (дампы УТ)

Все строки — `CommonModules/ОбменДаннымиXDTOСервер/Ext/Module.bsl` выгрузки trd.

### 4.1 Регистрация и отбор расширений

* `ДоступныеРасширенияФормата(ВерсияФорматаОбмена)` Экспорт — **:9538–9561**.
  Вызывает `ОбменДаннымиПереопределяемый.ПриПолученииДоступныхРасширенийФормата`
  (:9543), оставляет только те записи, чьё значение **равно** текущей версии
  формата обмена (:9548–9552), и выдаёт псевдонимы `ext1`, `ext2`, … (:9554).
* `ПоддерживаемыеОбъектыФормата` (:2820–2864): для каждой версии формата из
  настройки плана обмена `ВерсииФорматаОбмена` строится список расширений;
  если расширений нет — один проход с пустой схемой (базовый пакет), иначе
  цикл по расширениям, каждое включается в `КомпонентыОбмена`
  (`ВключитьПространствоИмен`) и правила обмена инициализируются отдельно.
  Поэтому состав «объект × отправка/получение» для расширенного пакета
  считается **своей копией** правил.

### 4.2 Как правило конвертации находит тип из расширяющего пакета

* При инициализации таблицы правил (:3971–4001) базовый `ТипXDTO` ищется
  `ФабрикаXDTO.Тип(ПространствоИмен, ОбъектФормата)`; если типа в базовом
  пакете нет, а расширения есть — `ТипXDTOПравилаКонвертацииИзРасширенийПакетаXDTO`
  (:4273) перебирает `ПравилоКонвертации.Расширения` и берёт тип из
  расширяющего пакета. Если и там не нашлось — **ПКО удаляется из таблицы**
  (:3988–3991); лишние расширения чистит `УдалитьИзбыточныеРасширенияПравилаКонвертации`
  (:4290).
* Экспортируемый хук для правил:
  `ИнициализироватьРасширениеПравилаКонвертацииОбъекта(ПравилоКонвертации, ПространствоИмен)`
  Экспорт — :4243, комментарий «Вызывается из правил»; вставляет в
  `ПравилоКонвертации.Расширения` структуру `{ТипXDTO, ТипКлючевыхСвойствОбъектаXDTO, ТипДанных}`.
* Отсюда нюанс статьи (задача 2): расширение определяется **по основному
  объекту формата** — если в расширяющий пакет не положить основной объект
  формата (даже без новых свойств у него), его ПКО просто выпадет из правил.

### 4.3 Расширенные свойства и пространство имён

* `ДополнитьСвойстваПакетаИзРасширений(ТипXDTO, СвойстваИсточника, КомпонентыОбмена, Расширения)`
  — :9590. Комментарий автора кода (:9598–9603) подтверждает: источник
  расширений — `ПриПолученииДоступныхРасширенийФормата`, а свойства из
  расширений добираются точечно (по правилам объекта), «иначе алгоритм будет
  работать при выгрузке всех объектов — потеря производительности».
* Колонка `ПространствоИмен` есть в таблице ПравилКонвертации и в ПКС
  (§3); при выгрузке узел расширенного свойства помечается URI расширения
  (в статье — префикс `расш:` внутри `<КлючевыеСвойства>`).

### 4.4 Неизвестное пространство имён на приёме

Перехвата «неизвестный namespace» в БСП нет: `ФабрикаXDTO.Тип()` с незнакомым
URI даёт исключение платформы. Практический смысл: **расширение (CFE с
XDTO-пакетом) обязано стоять на обеих сторонах**, иначе загрузка падает, а не
«игнорирует чужие поля» [проверено по коду дампов trd/buh; совпадает с
требованием статьи: у принятой стороны тот же URI и тот же порядок свойств,
иначе ошибка чтения файла].

## 5. Смежные факты

1. **Alternative-механизм в БП.** В дампе buh есть модули
   `РасширениеEnterpriseData`, `РасширениеEnterpriseDataКомандировки`
   (манифест `business_trips`) — JSON-расширение через `AdditionalInfo`.
   В дампе trd таких модулей нет. Это канал «конфигурация ↔ внешний мир»
   (бизнес-тревел), и стандартом v8std/771 п. 6 его использование в типовых
   обменах прямо запрещено — как обходной путь для нашей задачи он не
   рассматривается.
2. **Поле «Расширение формата» в интерактиве.** Форма обработки
   `ВыгрузкаЗагрузкаДанныхXDTO` (кнопка «Расширение формата») получает список
   из `ПриПолученииДоступныхРасширенийФормата` — то есть после регистрации в
   CFE расширение становится выбираемым и в ручной выгрузке/загрузке [дампы trd/buh].
3. **Менеджер конвертации — не переопределяемый модуль.**
   `МенеджерОбменаЧерезУниверсальныйФормат` (УТ) и
   `…13` (БП) — обычные общие модули конфигурации; правка их текста в
   базе на поддержке требует либо снятия с поддержки, либо заимствования
   модуля в CFE с последующим «Изменение и контроль». Точка расширения
   `ОбменДаннымиПереопределяемый` (версии формата и расширения) —
   напротив, штатный переопределяемый модуль БСП, и статья 6013 для
   регистрации вызывает именно так: процедура расширения сначала дёргает
   базовую, потом добавляет своё (`РасширенияФормата.Вставить(URI, "1.11")`)
   — автоматической цепочки вызова базовой реализации нет [статья, рис. 05].
4. **Вариант «менеджер-обёртка» к обмену по плану неприменим** (проверка
   дампов 04.11.2026). `ОбменДаннымиXDTOСервер.ВерсииФорматаОбмена`
   (:8697–8706) при переданном узле берёт соответствие «версия → модуль» из
   настройки узла `ВерсииФорматаОбмена` (:8704) и вызывает
   `ПриПолученииДоступныхВерсийФормата` только в ветке без узла (:8706).
   Значения настройки — общие модули конфигурации, модуль расширения туда не
   подставить. Для нашей пары остаётся заимствование менеджера (§7, п. 4);
   обёртка годится только для универсального обмена без плана.
