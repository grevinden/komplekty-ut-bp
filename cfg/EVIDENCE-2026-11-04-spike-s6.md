## 1. Подготовка баз

Работали на копиях `/tmp/opencode/exch/{ut,bp}`; расширение `КомплектыБП`
загружено в БП утилитой `ibcmd` (DESIGNER не запускался). Точная цепочка для
файловой базы без аутентификации 1С:

```bash
# создать расширение в базе (позиционный аргумент не принимается)
ibcmd extension create --db-path=/tmp/opencode/exch/bp --name=КомплектыБП

# залить объект(ы) расширения из XML; позиционные аргументы — ФАЙЛЫ,
# не имена объектов и не каталог
ibcmd config import files --db-path=/tmp/opencode/exch/bp --extension=КомплектыБП \
  --base-dir=/home/anton/Documents/minskaya/complect/tools/1c/ext/КомплектыБП \
  "CommonModules/МенеджерОбменаЧерезУниверсальныйФормат13.xml"

# применить
ibcmd config apply --db-path=/tmp/opencode/exch/bp --extension=КомплектыБП

# снять безопасный режим
ibcmd extension update --db-path=/tmp/opencode/exch/bp --name=КомплектыБП --safe-mode=no
```

Проверка дескриптора (`ibcmd extension list`):

```
name                         : "КомплектыБП"
version                      : "1.0.0.1"
active                       : yes
safe-mode                    : no
```

`ibcmd` держит монопольную блокировку файловой базы: два параллельных вызова
дают `Server data directory lock error`, перед запуском нужен `pkill -x 1cv8`.

## 2. Почему первые прогоны давали ноль строк

Первый прогон (см. §3) дал `товаров=` — в документе БП не было строк. Причина не
в обмене: **УТ выгружает строки `Товары` только у проведённых реализаций**. Замер
по копии УТ:

```
Н=0000-000001 | Пр=No  | Строк=2 | Сумма=1 497,4
Н=0000-000002 | Пр=No  | Строк=2 | Сумма=1 497,4
Н=ТД00-000015 | Пр=Yes | Строк=5 | Сумма=40 600
Н=ТД00-000016 | Пр=No  | Строк=2 | Сумма=1 100
```

В сообщении обмена у непроведённых документов блок `Товары` пуст, у
`ТД00-000015` — две строки товаров плюс услуга. То есть «пусто в БП» и «нет
строк в сообщении» — одно и то же.

Провести продажу набора удалось не с первого раза: на копии УТ не хватало
остатков по паре организация+склад. Сообщение при проведении:

```
По организации Торговый дом "Комплексный" на складе Торговый зал
не хватает 1 шт товара Вентилятор настольный
по налогообложению Продажа облагается НДС
```

Проведение смотрит `РегистрНакопления.ТоварыОрганизаций` (не `ТоварыНаСкладах`),
поэтому «на складе есть» по складовому регистру ничего не гарантирует.
Подошёл набор **«Мебельный гарнитур "Артон"»** (Кровать + Шкаф 3-дверный): у
Торгового дома на Мебельном складе было 22 и 18 шт. Продажа
`ТД00-000019` от 04.11.2026 21:19:30 проведена, две строки.

## 3. S6.1 — обработчик вызывается при загрузке

Расширение `КомплектыБП` с зондом в заимствованном общем модуле
`МенеджерОбменаЧерезУниверсальныйФормат13`
(`tools/1c/ext/КомплектыБП/CommonModules/МенеджерОбменаЧерезУниверсальныйФормат13/Ext/Module.bsl`):

```bsl

Зонд ничего не выбрасывает, всё пишет в `ПолученныеДанные.Комментарий` и в журнал

Первый прогон (сообщение 18, документ без строк) дал в БП:

```

  S6:сработал;товаров=;сборки-нет:товаров-меньше-двух

Отсюда: обработчик вызван (S6.1), но `ПолученныеДанные.Товары.Количество()` = 0 —
это shredded-документ, у которого в сообщении не было строк (§2).

## 4. S6.3 — первая попытка провести сборку упала на счетах

На проведённой продаже (`ТД00-000018`) зонд увидел две строки и создал
`Комплектацию номенклатуры`:

```
S6:сработал;товаров=2;сборка=0000-000039;проведена=нет:
Record is invalid! Both accounts are empty!
(Accounting register: Журнал проводок (бухгалтерский и налоговый учет); Line number: 1)
```

Ошибка не в перехвате: документ, созданный кодом, не проходит штатное
заполнение счетов. В БП счета заполняет механизм `СчетаУчетаВДокументах` в
`ПередЗаписью`, но только когда в дополнительных свойствах стоит флаг (проверено
по исходникам `Documents/КомплектацияНоменклатуры/Ext/ObjectModule.bsl`,
строка с `СчетаУчетаВДокументах.ЗаполнитьПередЗаписью(ЭтотОбъект, РежимЗаписи)`,
и `CommonModules/СчетаУчетаВДокументах`, функция `ЗаполнятьПередЗаписью`).

Лечение в зонде:

```bsl
Сборка.ДополнительныеСвойства.Вставить("ЗаполнитьСчетаУчетаПередЗаписью", Истина);
```

Правила заполнения для документа (`ManagerModule.bsl`, процедура
`УстановитьПравилаЗаполненияСчетовУчета`): шапка — `СчетУчета` по правилу
`ЗапасыКромеЗабалансовых`; строки `Комплектующие` — `СчетУчета` по тому же
правилу с источником `Номенклатура`.

## 6. Что осталось незакрытым

1. **Сумма проводки нулевая.** `ДоляСтоимости` в строках не заполнена, поэтому
   Дт/Кт 41.01 идут с `Сумма=0` (количество 0,5/1 — из-за `КоличествоДт` по
   комплекту). Для боевого алгоритма долю стоимости и суммы строк надо
   заполнять; на спайке это не требовалось, но в книге (§9.x) это ограничение
   надо назвать.
2. **Склад в документе БП пуст** (`Скл=`), как и в самой загруженной реализации.
   Правила конвертации EnterpriseData не переносят склад шапки
   `РеализацияТоваровУслуг` в БП. Для сборки это значит, что и склад сборки
   пуст, пока его не заполнить из строк или из настроек.
3. **Реализация в БП не проведена** (`Пр=No`) — штатная загрузка оставляет
   документы непроведёнными; это не мешает зонду, но боевой сценарий должен
   решать, кто проводит продажу.
4. Шаг 4 плана (замена строк набора строкой комплекта) не выполнялся.
