# Установка расширений на копии УТ и БП (05.11.2026)

## Контекст

Три расширения прототипа:
- `КомплектыОбмен` — ядро (общие модули свёртки + XDTO-пакет `КомплектыОбмен_EnterpriseData` + регистры `Настройки`, `СоответствиеНаборов`). Ставится на **обе** базы.
- `КомплектыБП` — адаптер приёма (БП). `&После`: регистрация XDTO, дополнение ПКО приёма, вызов свёртки в `ПередЗаписьюПолученныхДанных`.
- `КомплектыУТ` — адаптер отправки (УТ). `&После`: регистрация XDTO, дополнение ПКО отправки, заполнение пометки в `ПриОтправкеДанных`.

Платформа 8.3.27.2342. Формат EnterpriseData 1.20 (`EnterpriseData_1_20_2`), без обратной совместимости.

| Копия | Источник | Расширения |
|-------|----------|-----------|

| `/tmp/opencode/exch/ut` | DemoTrd 11.5.22.186 | КомплектыОбмен + КомплектыУТ |

## Способ установки (снимает блокер аутентификации УТ)

Блокер: `ibcmd extension *` и `infobase *` на копии УТ запрашивали аутентификацию и
висели на промпте (stdin закрыт `| tail` → дедлок). Копия БП создавалась без
аутентификации, поэтому там `ibcmd` работал без учётки.

Рабочий способ (проверен 05.11):

1. Загрузка XML-исходников расширения через DESIGNER (принимает `/N`):
   ```
   python3 .opencode/skills/db-load-xml/scripts/db-load-xml.py \
     -V8Path /opt/1cv8/x86_64/8.3.27.2342 \
     -InfoBasePath /tmp/opencode/exch/ut -UserName "Администратор" \
     -ConfigDir tools/1c/ext/<Расш> -Extension <Расш> -NoApplyCheck
   ```
   → «Load completed successfully».
2. Применение к конфигурации БД через `ibcmd config apply` — **режим `config`
   принимает `--user`** (в отличие от `extension list`/`config save -e`
   без учётки):
   ```
   ibcmd config apply --db-path=<копия> --user="Администратор" --data=<tmp> \
     -e <Расш> --force
   ```

Ключевой факт: **`--user`/`--password` понимает только `config`-режим ibcmd**
(`config load|save|check|apply`), а не `extension`-режим. Для файловой базы с
включённой аутентификацией (`DemoTrd`) без него команды падают/висят.

## Результат

- `config apply -e КомплектыОбмен` (УТ): `New object: РегистрСведений.КомплектыОбмен_СоответствиеНаборов`,
  «Database configuration successfully updated».
- `config check -e КомплектыУТ` / `-e КомплектыОбмен` (УТ): «Metadata validation completed».
- Копия БП: оба расширения применены ранее (generations `8e55fbca…`, `73a70083…`).

## Причина первоначального провала ПЕРЕХВАТ (05.11, ночь)

Перехват `&После` не срабатывал на обеих базах. Две независимые причины:

1. **Заимствованные модули содержали копию базового модуля.** В
   `КомплектыБП/CommonModules/ОбменДаннымиПереопределяемый/Ext/Module.bsl`
   (146 строк) лежал полный текст оригинала + наши методы — модель
   «доработки конфигурации», не расширения. Модуль загружался без ошибок,
   но добавления не сливались: `КомплектыБП_ТестСлияния` — «Object method
   not found». Сравнение с дампом спайка S1 (`/tmp/opencode/bp-ext-dump`,
   дескриптор байт-в-байт совпадает с теперешним) показало: работал там
   только **чисто аддитивный** модуль — `&После`-методы + свои методы, без
   копии оригинала. После перезаписи обоих адаптеров
   (`КомплектыБП`/`КомплектыУТ`, по 21 строке) слияние заработало: БП
   зазеленел сразу, УТ — после п. 2.
2. **Безопасный режим УТ-расширений.** После загрузки через
   `/LoadConfigFromFiles -Extension` расширения встают с
   `БезопасныйРежим=Истина` (в УТ копии); `&После`-перехватчик при этом
   не срабатывал. Снятие — режимом обработки `БЕЗОПАСНО`
   (`task.txt`: `режим = безопасно`, `расширение = <имя>`) дважды:
   КомплектыОбмен, затем КомплектыУТ. Флаг переживает сессии
   (проверка: повторный БЕЗОПАСНО показал «до: = No»). Снимок:
   `ut-ПЕРЕХВАТ.txt` 05.11 01:54 — «перехватчик &После СРАБОТАЛ»,
   URI `http://v8.1c.ru/edi/edi_stnd_ext_enterprisedata/EnterpriseData/1.20 = 1.20`,
   `КомплектыУТ_ТестСлияния` виден, безопасный режим=No. Это
   подтверждение требования спайка S1 «безопасный режим снять» на живой
   установке.

Побочная находка: в отчёте обработки `Формат(Булево; "БЛ=Да;БЛН=Нет")`
показывает **инверсию** (флаг No → «Да»). Вывод состояний булевых
свойств в диагностике — только `Строка()`; режим ПЕРЕХВАТ исправлен
(EPF пересобран 05.11 ~01:54).

## Итоговый порядок установки расширения на файловую базу (рабочий)

1. `db-load-xml.py ... -Extension <Р> -NoApplyCheck` (или DESIGNER
   `/LoadConfigFromFiles ... -Extension` вручную, если нужен лог).
2. `ibcmd config apply --db-path=<копия> [--user=...] --data=<tmp> -e <Р> --force`.
3. Снять безопасный режим: режим `БЕЗОПАСНО` обработки по каждому
   расширению (или `ibcmd extension update --safe-mode=no` — только для
   баз без аутентификации).
4. Приёмка: режим `ПЕРЕХВАТ` — URI расширения формата зарегистрирован,
   метод адаптера виден.
