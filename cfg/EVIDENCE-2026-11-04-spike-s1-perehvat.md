# Спайк S1: перехват методов расширением (04.11.2026)

Проверка на демо-базе **Бухгалтерия предприятия КОРП 3.0.208.14** (`/home/anton/Documents/1C/DemoBPprof`),
платформа **8.3.27.2342**. Диагностическая обработка — `tools/1c/diag/Обмен` (режимы
`ПЕРЕХВАТ`, `ПЕРЕХВАТДОК`, `БЕЗОПАСНО`, `КОНТУР`), собирается в `/tmp/opencode/Обмен.epf`.

## 1. Что проверялось

Работают ли в этом окружении три механизма внедрения в чужой код:

1. аннотация `&После` на методе **заимствованного общего модуля**;
2. аннотация `&После` на методе **модуля объекта заимствованного документа**;
3. **подписка на событие**, объявленная в расширении.

Повод: в первой серии опытов (тот же день, до 19:00) все три механизма «не срабатывали» —
ни один не оставлял файла-маркера. Этот результат оказался ложным, см. §4.

## 2. Состав расширения `КомплектыБП`

Каталог `tools/1c/ext/КомплектыБП`, назначение `AddOn`, префикс `КомплектыБП_`,
совместимость `Version8_3_27`.

| Объект | Тип | Роль в опыте |
|---|---|---|
| `ОбменДаннымиПереопределяемый` | заимствованный общий модуль | `&После("ПриПолученииДоступныхРасширенийФормата")` + собственный экспортный метод `КомплектыБП_ТестСлияния()` |
| `КомплектацияНоменклатуры` | заимствованный документ | `&После("ОбработкаПроверкиЗаполнения")` в модуле объекта |

Загрузка — `db-load-xml.py ... -Extension "КомплектыБП" -UpdateDB`, вывод
`Load completed successfully`. Выгрузка обратно в файлы подтверждает, что аннотации и
подписка доехали до базы без искажений.

## 3. Результаты

### 3.1. `&После` на заимствованном общем модуле — работает

Режим `ПЕРЕХВАТ` вызывает `ОбменДаннымиПереопределяемый.ПриПолученииДоступныхРасширенийФормата(РасширенияФормата)`.
Обработчик-перехватчик делает `ВызватьИсключение`, и вызов падает:

```
ОШИБКА вызова: {КомплектыБП ОбщийМодуль.ОбменДаннымиПереопределяемый.Модуль(9)}:
  спайк S1: аннотация &После на общем модуле сработала
```

Собственный новый метод того же заимствованного модуля виден снаружи:
`метод расширения виден: новый метод общего модуля виден`.

### 3.2. `&После` на модуле объекта заимствованного документа — работает

Режим `ПЕРЕХВАТДОК` создаёт документ и вызывает `ПроверитьЗаполнение()`:

```
  {КомплектыБП Документ.КомплектацияНоменклатуры.МодульОбъекта(9)}:
  спайк S1: аннотация &После на модуле объекта сработала
```

### 3.3. Подписка на событие из расширения — работает

Обработчик подписки ставил `Отказ = Истина`. Запись документа падала:

```
исключение при записи: Error calling context method (Записать): Error running processor -
  'ПередЗаписью': {КомплектыБП ОбщийМодуль.КомплектыБП_Тест.Модуль(28)}:
  спайк S1: подписка сработала; ...
```

Документ, записанный без отказа, появился в базе и был удалён тем же прогоном
(`Комплектация номенклатуры 0000-000026`).

## 4. Почему первая серия опытов дала ложный отрицательный результат

Расширение при загрузке через `/LoadConfigFromFiles -Extension` встаёт в базу
**в безопасном режиме**. В безопасном режиме запрещены файловые операции, поэтому
обработчики падали на `Текст.Записать(...)` **до** записи маркера, а исключение
глушилось `Попытка`. Наблюдаемый признак «файла нет» был истолкован как
«обработчик не вызван». Прямая цитата из прогона:

```
спайк S1: подписка сработала; файл записан=No; ошибка записи файла:
  Error calling context method (Записать):
  The operation is not allowed because the application is running in safe mode.
```

### Как снять безопасный режим

Свойство живёт в дескрипторе расширения (не в `Configuration.xml`), меняется из кода:

```bsl
Для Каждого Элемент Из РасширенияКонфигурации.Получить() Цикл
    Если Элемент.Имя = "КомплектыБП" Тогда
        Элемент.БезопасныйРежим = Ложь;
        Элемент.Записать();
    КонецЕсли;
КонецЦикла;
```

Проверено: флаг **переживает** повторную загрузку расширения из файлов
(`/LoadConfigFromFiles` после снятия — `безопасный режим=No`), но для новой базы
его нужно снимать отдельно.

Состояние в демо-базах на 04.11.2026: `КомплектыОбмен` и `КомплектыБП` — активно,
безопасный режим снят.

## 5. Выводы для плана

1. **Fallback §3.5 плана не нужен.** Копировать менеджеры обмена (`83 364` строк УТ,
   `55 492` строк БП) не требуется: `&После` на заимствованных общих модулях работает,
   значит расширение формата EnterpriseData через
   `&После("ПриПолученииДоступныхРасширенийФормата")` и `&После("ДобавитьПКО_...")` доступно.
2. Триггер автозапуска можно строить и на аннотации
   (`&После("ЗафиксироватьЗавершениеОбмена")`), и на подписке на событие — оба механизма
   рабочие. Выбор — по смыслу события, а не по доступности механизма.
3. **Требование к установке расширений: безопасный режим снять.** Иначе нельзя ни писать
   диагностические файлы, ни (потенциально) работать с внешними файлами провайдера
   «Ручной». Проверяется в приёмке (U-критерии) и описывается в инструкции по установке.
4. Диагностика расширений в этом проекте должна сигналить **исключением** или записью в
   документ, а не файлом: файл молча не пишется в безопасном режиме.

## 7. Как воспроизвести

```bash
cd /home/anton/Documents/minskaya/complect
timeout 600 python3 .opencode/skills/db-load-xml/scripts/db-load-xml.py \
  -InfoBasePath "/home/anton/Documents/1C/DemoBPprof" \
  -ConfigDir "tools/1c/ext/КомплектыБП" -Mode Full -Extension "КомплектыБП" -UpdateDB

/opt/1cv8/x86_64/8.3.27.2342/1cv8 DESIGNER /F"/home/anton/Documents/1C/DemoTrd" \
  /N"Администратор" /DisableStartupDialogs /DisableStartupMessages \
  /LoadExternalDataProcessorOrReportFromFiles "tools/1c/diag/Обмен.xml" \
  /tmp/opencode/Обмен.epf

printf 'имя = bp\nрежим = перехват\n' > /tmp/opencode/exch/task.txt
/opt/1cv8/x86_64/8.3.27.2342/1cv8 ENTERPRISE /F"/home/anton/Documents/1C/DemoBPprof" \
  /DisableStartupDialogs /DisableStartupMessages /Execute /tmp/opencode/Обмен.epf
cat /tmp/opencode/exch/bp-ПЕРЕХВАТ.txt
```

Режимы: `КОНТУР` (список расширений и флагов), `ПЕРЕХВАТ` (аннотация общего модуля),
`ПЕРЕХВАТДОК` (аннотация модуля объекта), `БЕЗОПАСНО` (снять безопасный режим),
`ПЕРЕХВАТ`/`ПЕРЕХВАТДОК` — только в БП: в УТ нет документа `КомплектацияНоменклатуры`.
