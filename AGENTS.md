Это информационный проект. Здесь мы изучаем возможности создания и использования комплектов и наборов в конфигурациях 1С:

- Управление торговлей, редакция 11 (11.5.22.186)

- Бухгалтерия предприятия КОРП, редакция 3.0 (3.0.208.14)

Вопросы, которые нужно решить, как создавать комплекты и наборы управлению торговлей и передавать информацию об операционных действиях в бухгалтерию предприятия.

## Проверки на живых базах (как это делалось 31.10–01.11.2026)

- Диагностическая обработка: `tools/1c/diag/Пробник/` (XML-исходники) → сборка
  `/opt/1cv8/x86_64/8.3.27.2342/1cv8 DESIGNER ... /LoadExternalDataProcessorOrReportFromFiles`;
  запуск `ENTERPRISE ... /Execute <epf>`. Снимки прогонов — `tools/1c/diag/out/diag_*.txt`.
- Результаты проверок не пишутся прямо в книгу: сначала `cfg/EVIDENCE-<дата>-*.md`
  с координатами (момент прогона, версия конфигурации, путь к снимку), потом — довод
  в `docs/` со ссылкой на файл `cfg/` **полным адресом GitHub** (`cfg/` на сайт
  не публикуется, относительная ссылка даст 404).
- БП 3.0.208.14 (`DemoBPprof`) принимает внешние обработки; УТ 11.5.22.186 (`DemoTrd`)
  на платформе 8.3.27.2342 падает при `/Execute` («К сожалению, возникла
  непредвиденная ситуация»), `DESIGNER` при этом работает — ограничение
  зафиксировано в `cfg/EVIDENCE-2026-11-01-menu.md`, §6.3.
- Снимок экрана под XWayland: root-снимок чёрный, GNOME Shell через gdbus даёт
  AccessDenied — снимать окно `XGetImage` (`/tmp/opencode/xgrab.py`), синтетический
  ввод — `/tmp/opencode/xkey.py`, чтение текста — локальный tesseract в `/tmp/opencode/ocr`.
- `pkill -x 1cv8` (не `pkill -f "1cv8 ENTERPRISE"` — убивает собственный shell).

## Методические правила проекта

- Каждую нетривиальную фразу подтверждать цитатой; неподтверждённое помечать [НЕ ПОДТВЕРЖДЕНО ИТС] / [ВЕБ 1] / [ВЕБ 2+] / [ВЫВОД].
- Сохранять источники информации обязательно: каждый довод в учебнике, словаре и отчётах
  сопровождается ссылкой на исходник — координата ИТС (`ut8doc/339`, `bp8doc/160` и т. п.),
  полный URL с датой обращения, путь к артефакту (дамп правил, снимок экрана) или цитата
  в `its/EVIDENCE-*.md`. Цитаты — дословные; при переносе довода между файлами ссылка
  переезжает вместе с ним. Довод без исходника в текст не попадает, а переносится
  в «Отрицательные проверки» или в вопросы оператору (§9.5).
- Проводки Дт/Кт не выдумывать: ИТС их не публикует — брать из базы пользователя или помечать как реконструкцию сообщества.
- Доступ к ИТС — только через живую браузерную сессию пользователя; секреты ИТС в файлы не писать.
- Веб-находки попадают сначала в net/NN-отчёт, затем сводно в главу 9 (§9.x), и только проверенные — в главы 1–7.
- Субагентам веб-фронтов its.1c.ru запрещён; бесплатный лимит моделей исчерпан — субагенты идут на модели по умолчанию.
- В Code Mode (`execute`) нет инструмента `edit`; правки файлов — прямыми вызовами `edit`.
- Схемы — mermaid `flowchart TB`: подписи блоков начинаются с «УТ 11.5 ·» / «БП 3.0 ·», все смысловые связи — видимыми стрелками с подписью; невидимые `~~~` допустимы только для ранжирования. Итоговая схема главы 1 согласована с владельцем.
- При написании кода BSL Обязательная проверка LSP
