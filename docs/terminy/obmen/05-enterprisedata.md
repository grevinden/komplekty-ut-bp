# EnterpriseData

**EnterpriseData** универсальный формат переноса данных между типовыми конфигурациями 1С. В интерфейсе он называется «универсальный формат обмена данными»: в настройках обмена пары конфигураций выбирается именно он, а не прямой «из УТ в БП». [ПЛАТФОРМА/ВЕБ 2+, подтверждается практикой патчей, отчёт 09]

Работает так: отправитель превращает свой объект в сообщение универсального формата, получатель собирает из сообщения свой объект. Между двумя «родными» форматами два перевода, и каждый живёт по своим правилам конвертации. У формата есть версия: на баг-борде 1С разбирался сбой импортёра формата 1.17 (случай с комплектами, 000167756) [ВЕБ 1, отчёт 09].

Исполняет правила модуль «МенеджерОбменаЧерезУниверсальныйФормат» и связанные общие модули: там перечни объектов и полей, там же точки для пользовательских изменений [ВЕБ 2+, отчёт 09]. Если какое-то сопоставление мешает или отсутствует, его правят расширением через `&ИзменениеИКонтроль` (добавить/изменить/`#Удаление` строку ПКО), не снимая конфигурацию с поддержки [ВЕБ 2+, отчёт 09].

Почему это важно для комплектов. Набор объектов и полей формата конечен. Документ или свойство, которых нет в правилах формата, физически не помещается в сообщение. Но со сборкой это как раз не проблема: `Документ.СборкаТоваров` в формате есть — вместе с видом операции (`Сборка` или `Разборка`), строками `Товары` с `ДоляСтоимости` и `Себестоимость`. Чего в формате и в конфигурации нет — готового правила превращения этого документа в документ БП: этим занимается принимающая сторона, и здесь начинается зона теста, а не чтения схемы ([§5.3](../../05-perenos-dannyh.html#5.3), [§5.4](../../05-perenos-dannyh.html#5.4)). Тот же механизм объясняет тип `Набор-комплект`: в перечне выгружаемых типов его нет ([§5.5](../../05-perenos-dannyh.html#5.5)).

Отсюда житейское правило: «обмен не переносит то, чего нет в формате». Прежде чем искать баг, стоит проверить, есть ли объект в правилах.
