# План обмена и узел

**План обмена** это объект метаданных платформы: список видов документов и справочников, которые база готова обсуждать с собеседниками по обмену. Не виденный в плане обмена документ в обмен не поедет никогда, какие бы настройки ни крутили. [ПЛАТФОРМА: общее из документации 1С, пояснение редактора]

У каждой базы есть **план обмена узла**:Personalная копия этого списка с галочками «в этом направлении обмен вести / не вести». Настройки обмена в интерфейсе типовых конфигураций (Справочники, Документы) по сути и есть расстановка этих галочек. [ПЛАТФОРМА]

**Узел обмена** зарегистрированный в базе собеседник: имя, способ связи (файл, почта, tcp-соединение, веб-адрес), настройки безопасности, дата последнего обмена. В паре оператора их два: узел УТ и узел БП.

Почему это важно для нашей темы. Если документ «не выгружается», первый вопрос не «где баг», а «включён ли вид документа в настройки обмена и есть ли он в плане обмена конфигурации». Для складских документов комплектов это проверяется по обоим направлениям: сборка в УТ и комплектация в БП разные метаданные, и галочка нужна в каждой базе своя. Практика форумов: пользователи годами ждут «двусторонней синхронизации», хотя в типовой связке УТ 11 → БП 3.0 документооборот по складу однонаправленный [ВЕБ 2+, см. отчёт 01, отчёт 09].
