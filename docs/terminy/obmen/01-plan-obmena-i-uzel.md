# План обмена и узел

**План обмена** это объект метаданных платформы: список видов документов и справочников, которые база готова обсуждать с собеседниками по обмену. В механизме «по плану обмена» документ, которого нет в составе плана, из этой базы не уедет. Но это ограничение на **отправку**: в универсальном формате (EnterpriseData) приём задаётся правилом получения по типу формата, а не составом плана. Пример из выгрузки БП 3.0.208.14: `Document.КомплектацияНоменклатуры` в плане `СинхронизацияДанныхЧерезУниверсальныйФормат` отсутствует, а сборка из УТ всё равно принимается (§5.3–5.4). [конфигурация БП 3.0.208.14: `ExchangePlans/СинхронизацияДанныхЧерезУниверсальныйФормат/Ext/Content.xml`, `CommonModules/МенеджерОбменаЧерезУниверсальныйФормат13`]

У каждой базы есть **план обмена узла**: персональная копия этого списка с галочками «в этом направлении обмен вести / не вести». Настройки обмена в интерфейсе типовых конфигураций (Справочники, Документы) по сути и есть расстановка этих галочек. [ПЛАТФОРМА]

**Узел обмена** зарегистрированный в базе собеседник: имя, способ связи (файл, почта, tcp-соединение, веб-адрес), настройки безопасности, дата последнего обмена. В паре оператора их два: узел УТ и узел БП.

Почему это важно для нашей темы. Если документ «не выгружается», первый вопрос не «где баг», а «зарегистрирован ли документ к отправке». Для сборки в УТ 11.5.22.186 ответ виден в составе плана: `Документ.СборкаТоваров` в плане есть, но с `AutoRecord = Deny` — автоматическая регистрация выключена, документ надо ставить к отправке вручную (§5.4). В БП своя галочка для приёма не нужна: правило получения включено в коде. Практика форумов: пользователи годами ждут «двусторонней синхронизации», хотя в типовой связке УТ 11 → БП 3.0 документооборот по складу однонаправленный [ВЕБ 2+, см. отчёт 01, отчёт 09].
