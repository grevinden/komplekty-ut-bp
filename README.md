# Комплекты и наборы в УТ 11.5 и БП 3.0

Проект исследования: как устроены комплекты/наборы в «Управлении торговлей» 11.5
и «Комплектации номенклатуры» в БП 3.0 КОРП, и что ломается при переносе УТ → БП.

## Публикация (GitHub Pages)

Один репозиторий: **https://github.com/grevinden/komplekty-ut-bp**, сайт
**https://grevinden.github.io/komplekty-ut-bp/**. GitHub Pages собирает его
штатным Jekyll из папки [`docs/`](docs/index.md) ветки `main`
(Settings → Pages → Branch `main`, folder `/docs`). Второго каталога и синхронизации нет.

Порядок правки: редактируете `docs/**/*.md`, затем `./publish-site.sh "комментарий"` —
скрипт коммитит, пушит и ждёт сборку Pages.
Каждая страница начинается с YAML-шапки (`layout`, `title`) — Jekyll по ней превращает `.md`
в HTML-страницу; ссылки между страницами ведут на `.html`-имена.

Репозиторий публичный, поэтому рабочие материалы в нём тоже видны (они не попадают
на сайт: Pages публикует только `docs/`).

## Что где лежит

- `docs/` — опубликованное издание: страница для руководителя (`00-direktoru.md`),
  обложка-оглавление (`index.md`), главы 01–09, словарь терминов `terminy/`.
- `net/01`–`net/09` — отчёты поисковых фронтов (рабочие материалы, на сайт не входят).
- `its/EVIDENCE-2026-10-30.md` — цитаты ИТС с координатами.
- `cfg/EVIDENCE-<дата>-*.md` — протоколы проверок на живых демо-базах: что
  запускали, что получилось, где снимок (на сайт не входят).
- `tools/1c/diag/` — диагностическая обработка 1С и снимки её прогонов.
- `RESEARCH-plan.md`, `PLAN-2026-11-01.md`, `AGENTS.md` — планы и правила работы.

`.handoff/` в репозиторий не попадает (в нём ключи доступа ИТС), см. `.gitignore`.
